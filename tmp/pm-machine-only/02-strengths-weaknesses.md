# 02-strengths-weaknesses

## 优点
- 分层清晰：后端 `router/api/service/model` 与前端 `router/pinia/view/api` 结构稳定。
- 自动化能力强：内置代码生成、模板管理、工作流编排。
- AI工具链完整：具备 MCP 独立服务与工具注册机制。
- 扩展性较好：插件支持后端与前端双侧集成。
- 基础设施兼容面广：数据库/对象存储配置项覆盖较多。
- 部署资产齐全：提供 Docker 与 Kubernetes 示例。

## 缺点
- 全局状态使用较多（`global.*`），模块独立测试与并行演进成本增加。
- 业务与平台能力耦合度偏高（如系统管理、自动代码、MCP 同仓并行演进）。
- 文档与实现存在规模差，手工阅读成本高，需要依赖索引化检索。
- 自动化测试覆盖有限：当前纳入范围仅检测到 18 个测试文件。

## 维护建议
- 通过 `segment_id` 作为最小知识单元，优先做按域检索再展开代码。
- 对超长逻辑段优先拆分，降低后续模型上下文成本。
- 将高频问题沉淀为 Prompt 模板并固定检索顺序。
